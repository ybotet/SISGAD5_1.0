# Бизнес-правила - SISGAD5

> **Версия:** 1.0
> **Дата:** 2026-09-25

---

## 1. Правила Аутентификации и Авторизации

| ID         | Правило                     | Описание                                                               |
| ---------- | --------------------------- | ---------------------------------------------------------------------- |
| RN-AUTH-01 | **Политика пароля**         | Минимум 8 символов, 1 заглавная, 1 строчная, 1 цифра, 1 специальный    |
| RN-AUTH-02 | **Блокировка аккаунта**     | 5 неудачных попыток → блокировка 15 минут                              |
| RN-AUTH-03 | **Ротация Refresh Token**   | Каждое использование отзывает предыдущий (ротация + обнаружение кражи) |
| RN-AUTH-04 | **Истечение Access Token**  | 15 минут (настраивается через env)                                     |
| RN-AUTH-05 | **Истечение Refresh Token** | 7 дней (настраивается через env)                                       |
| RN-AUTH-06 | **Параллельные сессии**     | Максимум 3 активных сессий на пользователя                             |
| RN-AUTH-07 | **RBAC Строгое**            | Доступ запрещен по умолчанию (deny-by-default)                         |

## 2. Правила Инфраструктуры MP

| ID       | Правило                   | Описание                                                                |
| -------- | ------------------------- | ----------------------------------------------------------------------- |
| RN-MP-01 | **Уникальность Телефона** | Номер телефона уникален в БД                                            |
| RN-MP-02 | **Уникальность Линии**    | Номер линии уникален в БД                                               |
| RN-MP-03 | **Панель-Порт**           | Порт уникален для каждой панели (составной: pizarra_id + numero_puerto) |
| RN-MP-04 | **Клиент Обязателен**     | Телефон/Линия/Панель должны иметь связанного клиента                    |
| RN-MP-05 | **Логическое удаление**   | Смена на "baja" не удаляет, только помечает статус + fecha_baja         |
| RN-MP-06 | **Целостность истории**   | Никогда не удалять записи истории (только append)                       |

---

## 3. Правила Жалоб

| ID        | Правило                            | Описание                                                                                    |
| --------- | ---------------------------------- | ------------------------------------------------------------------------------------------- |
| RN-QUE-01 | **Обязательная классификация**     | Каждая жалоба должна иметь: tipo_queja, servicio, ubicacion (FK-ключи)                      |
| RN-QUE-02 | **Автоматический приоритет**       | Вычисляется по: tipo_queja.peso + servicio.peso + ubicacion.peso + antigüedad               |
| RN-QUE-03 | **Строгий поток состояний**        | Только разрешенные переходы: Abierta→Probada→Asignada→Pendiente→Resuelta→Cerrada            |
| RN-QUE-04 | **Запрещено пропускать состояния** | Запрещено: Abierta→Asignada, Probada→Resuelta и т.д.                                        |
| RN-QUE-05 | **Назначение требует техника**     | Только пользователи с ролью "Техник" могут быть назначены                                   |
| RN-QUE-06 | **Закрытие требует теста**         | Состояние "Cerrada" только если есть связанная пробная запись с exitoso=true                |
| RN-QUE-07 | **Повторное открытие**             | "Cerrada" жалоба может быть повторно открыта → возвращается в "Abierta" (новый num_reporte) |
| RN-QUE-08 | **Непизменяемый аудит**            | Каждый переход фиксирует: usuario_id, estado_anterior, estado_nuevo, timestamp, IP          |

## 4. Правила Тестов

| ID        | Правило                 | Описание                                                               |
| --------- | ----------------------- | ---------------------------------------------------------------------- |
| RN-PRU-01 | **Обязательная связь**  | Тест должен быть связан с queja_id И/ИЛИ trabajo_id (хотя бы один)     |
| RN-PRU-02 | **Бинарный результат**  | Поле "exitosо": true/false (без промежуточных состояний)               |

---

## 5. Правила Работ

| ID        | Правило                                | Описание                                                          |
| --------- | -------------------------------------- | ----------------------------------------------------------------- |
| RN-TRA-01 | **Реальное время ≤ Оценка × 2**        | Оповещение если реальное время превышает 2× оценку (не блокирует) |
| RN-TRA-02 | **Закрытие требует реального времени** | Поле real_horas обязательно при закрытии                          |

## 6. Правила Материалов

| ID        | Правило                              | Описание                                                                      |
| --------- | ------------------------------------ | ----------------------------------------------------------------------------- |
| RN-MAT-01 | **Уникальный код материала**         | Алфавитно-цифровой код уникален (ej: MAT-001, CAB-UTP-CAT6)                   |
| RN-MAT-02 | **Положительная цена**               | precio_unitario > 0 в каталоге                                                |
| RN-MAT-03 | **Категория/Единица обязательна**    | FK не NULL для материала                                                      |
| RN-MAT-04 | **Ссылочная целостность**            | Не удалять категорию/единицу если есть материалы (RESTRICT)                   |
| RN-MAT-05 | **Атомарное назначение**             | Все позиции назначаются или ни одна (транзакция)                              |
| RN-MAT-06 | **Цена момента заморожена**          | costo_unitario_momento не изменяется после создания назначения                |
| RN-MAT-07 | **Расход ≤ Назначение в ожидании**   | Σ(consumos) ≤ Σ(asignaciones) - Σ(consumos_previos) по материалу/пользователю |
| RN-MAT-08 | **Атомарный расход**                 | Все позиции расходуются или ни одна (транзакция)                              |
| RN-MAT-09 | **Логический склад неотрицательный** | Баланс = Назначено - Расходовано ≥ 0 всегда                                   |
| RN-MAT-10 | **Допустимый техник**                | Только пользователи с ролью "Техник" или "Analista" могут получать назначения |

## 7. Правила Дашборда и Аналитики

| ID         | Правило                       | Описание                                            |
| ---------- | ----------------------------- | --------------------------------------------------- |
| RN-DASH-01 | **KPI в реальном времени**    | Дашборды запрашивают БД напрямую (без кеша > 5 мин) |

| RN-DASH-03 | **Настраиваемые оповещения**  | Пороги низкого склада по материалу/категории        |

## 8. Технические правила (Трансверсальные)

| ID        | Правило                             | Описание                                                                 |
| --------- | ----------------------------------- | ------------------------------------------------------------------------ |
| RN-TEC-01 | **Soft Delete**                     | Никогда физический DELETE; использовать deleted_at / estado = 'baja'     |
| RN-TEC-02 | **Timestamps**                      | created_at, updated_at обязательны для всех таблиц                       |
| RN-TEC-03 | **Оптимистическое версионирование** | Поле version (integer) для обнаружения конфликтов одновременного доступа |
| RN-TEC-04 | **Уникальные ID**                   | UUID v4 для основных сущностей, автоинкремент integer для каталогов      |
| RN-TEC-05 | **Стандартная пагинация**           | ?page=1&limit=10 (max 100) для всех списков                              |
| RN-TEC-06 | **Стандартная сортировка**          | ?sortBy=campo&sortOrder=ASC                                              |DESC 
| RN-TEC-07 | **Стандартный поиск**               | ?search=texto ищет в соответствующих полях по сущности                   |
| RN-TEC-08 | **Стандартный ответ**               | {success: bool, data: T, pagination?, error?}                            |
