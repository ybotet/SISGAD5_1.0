## 2026-10-30 — TASK-600-04: Verificación de JWT + Infraestructura de Tests Gateway

### Estado: ✅ Completada

### Qué se hizo

#### 1. Verificación de JWT en API Gateway
1. **docker-compose.yml** — Añadida variable de entorno `JWT_SECRET=${JWT_SECRET}` al servicio `api-gateway`. Sin esto, el gateway fallaba al arrancar en Docker porque `requireJwtSecret()` arroja si `JWT_SECRET` no está presente o tiene menos de 32 caracteres.
2. **rateLimit.js** — Eliminada definición duplicada de `authLimiter` (hallazgo QA-04). Restaurada a una sola definición en `module.exports`. El archivo original tenía `authLimiter` dentro del objeto `module.exports` (línea 9) y una redefinición separada en `module.exports.authLimiter` (línea 18), donde la segunda anulaba la primera.

#### 2. Infraestructura de Tests (Jest + Supertest)
1. **jest.config.js** — Creado siguiendo el patrón de `backend-users/jest.config.js`:
   - `testEnvironment: "node"`
   - `testMatch: ["**/tests/**/*.test.js"]`
   - `testTimeout: 15000`
   - `verbose: true`
2. **package.json** — Añadidos `jest@^29.7.0` y `supertest@^7.3.1` en `devDependencies`. Añadido script `"test": "jest"`.
3. **tests/verifyJwt.test.js** — 10 tests cubriendo:
   - `requireJwtSecret()`: rechaza secreto ausente, <32 chars, acepta ≥32 chars
   - JWT middleware: rutas públicas (health) sin token → 200, falta Authorization → 401, formato no Bearer → 401, token con secret equivocado → 401, token expirado → 401, token válido → pasa verificación y propaga `req.user`

#### 3. Optimización del auth.controller.js (backend-users)
1. **Eliminados** `validarEmail()` y `validarPassword()` (116 líneas → 0). Estas funciones eran redundantes: la validación de email/password ya se realiza en la capa de rutas vía Zod (`loginSchema` en `auth.validation.js`), aplicada por el middleware `validate()` antes de que el controlador se ejecute.
2. **Simplificado** el flujo `login()`: eliminados los bloques duplicados de validación + registro de sesión de error (antes ocurrían 3 veces). Ahora el controlador va directamente a buscar el usuario y validar credenciales.
3. **Extraída** la lógica de cálculo de expiración a una función reutilizable `calcularExpiry()` (regex `^(\d+)([dhm])$` con match, más concisa que el if/else chain original).
4. **Simplificada** `crearRefreshToken()`: la lógica de cálculo de expiración ahora usa `calcularExpiry()`.
5. **Eliminarado** import de `crypto` (solo se usaba en las funciones de validación eliminadas).
6. Todas las funciones documentadas con JSDoc en español.

### Frontend — TeléfonoDetallesModal (Rediseño Moderno)

1. **Bug fix — `recargarRecorridos`**: La condición `else if` verificaba `response.data && Array.isArray(response.data)` (idéntica al `if` anterior). Corregido a `response.data?.data && Array.isArray(response.data.data)`.
