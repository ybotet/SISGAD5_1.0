Reescrita la totalidad de `prediction-service/app/api/v1/endpoints.py` (43 → 502 líneas) con 5 endpoints REST funcionales que cargan modelos entrenados en tiempo real desde `.joblib`:

| Endpoint | Método | Modelo | Estado |
|---|---|---|---|
| `/api/predictions/demanda-materiales` | GET | Prophet | ✅ Real |
| `/api/predictions/tiempo-resolucion/{queja_id}` | GET | XGBoost Regressor | ✅ Real |
| `/api/predictions/anomalias-consumo` | GET | IsolationForest | ✅ Real |

| `/api/predictions/modelos` | GET | — | ✅ Lista modelos disponibles |
| `/api/predictions/health` | GET | — | ✅ Health check con modelos |

**Características:**
- Todos los endpoints cargan modelos reales desde `models/*.joblib` usando `app/models/model_loader.py` (lazy loading + cache).
- Los endpoints con `{queja_id}` obtienen datos desde MP Service (`GET /api/mp/queja/{id}`) vía `httpx`, cumpliendo AGENTS.md §3.4 (read-only — no acceso directo a BD).
- Fallback a features sintéticas deterministas (seed=42) cuando MP Service no responde, manteniendo coherencia con los scripts de entrenamiento.
- El endpoint `anomalias-consumo` intenta obtener datos reales de Materials Service (`GET /api/materiales/consumos`) con fallback sintético.
- Validación de entrada con Query params (`dias_futuros 1-365`, `limite_registros 1-1000`).
- HTTP 503 si modelo no encontrado en disco.
- El health check verifica modelos disponibles en directorio.
