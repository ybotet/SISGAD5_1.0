## 2026-11-02 — Bloqueo por intentos fallidos (TASK-300-07)

### Resumen
Implementado bloqueo temporal de cuenta por intentos fallidos de login en el Users Service. Después de N intentos fallidos (configurable, default 5), la cuenta se bloquea por 15 minutos (configurable). Al alcanzar el umbral se revocan todas las sesiones activas y se registra evento de auditoría.

### Archivos creados/modificados
| Archivo | Cambio |
|---------|--------|
| `backend-users/src/migrations/20261102000003-add-login-lock-columns.js` | Nueva migración: añade `failed_attempts` (int default 0) y `locked_until` (timestamptz null) a `tb_user` |
| `backend-users/src/features/user/user.model.js` | Añadidas columnas `failed_attempts` y `locked_until` al modelo TbUser |
| `backend-users/src/features/auth/auth.controller.js` | `login()` modificado: verifica `locked_until` → 423 con `retry_after`; incrementa `failed_attempts` en fallos; bloquea al alcanzar umbral; resetea en éxito; evento de auditoría vía `registrarSesion`; mensaje genérico sin revelar existencia de email |
| `backend-users/tests/auth.test.js` | 5 tests nuevos: 5 fallos→bloqueo, login durante bloqueo→423, éxito resetea, expiración libera, mensaje genérico |
| `TASKLIST.md` | TASK-300-07 → ✅; subtotal FASE 3 → 90.9%; TOTAL → ≈70.3% |

### Variables de entorno
| Variable | Default | Descripción |
|----------|---------|-------------|
| `LOGIN_MAX_ATTEMPTS` | 5 | Número máximo de intentos fallidos antes de bloquear |
| `LOGIN_LOCK_MINUTES` | 15 | Duración del bloqueo en minutos |

### Flujo de seguridad
1. Login con `locked_until > ahora` → **423** con `retry_after` (minutos restantes)
2. Credenciales inválidas → incrementar `failed_attempts`; si ≥ `LOGIN_MAX_ATTEMPTS` → establecer `locked_until = ahora + LOGIN_LOCK_MINUTES`
3. Login exitoso → resetear `failed_attempts = 0` y `locked_until = null`
4. Evento de auditoría estructurado al bloquear (id_usuario, ip, detalle)
5. Mensaje de error genérico: "Credenciales inválidas" (no revela si el email existe)

### Tests (5 tests, todos pasando)
1. 5 fallos consecutivos → cuenta bloqueada, `update` llamado con `{failed_attempts: 5, locked_until: Date}`
2. Login durante bloqueo → **423** con `retry_after > 0`, `verificarPassword` no llamado
3. Login exitoso tras fallos previos → `update` llamado con `{failed_attempts: 0, locked_until: null}`
4. Cuenta bloqueada expirada → login exitoso, intentos reseteados
5. Email no registrado → **401** "Credenciales inválidas" (sin revelar existencia)

- 2 suites: jwt.test.js (9 tests) + auth.test.js (22 tests)
