### Qué se hizo

- Actualizado `.env.local` con los nuevos valores de `JWT_SECRET` y `DB_PASSWORD`.
- Actualizado `backend-materiales-go/.env` con la nueva `DB_PASSWORD`.
- Actualizado `.env.example` con placeholders seguros: `JWT_SECRET=your_very_long_random_jwt_secret_here_at_least_32_chars` y `DB_PASSWORD=your_secure_password_here`.
- Eliminados los archivos `.env`, `.env.docker`, `.env.production` (modo local únicamente).
- Verificado que `.gitignore` excluye correctamente `.env.local`, `.env`, `.env.*`, y `**/.env` / `**/.env.*`, mientras mantiene `.env.example` versionado.

### Por qué se hizo de esa forma
- El `JWT_SECRET` era `el_token_mas_seguro_del_mundo_2025` (valor estático, predecible) y `DB_PASSWORD` era `postgres` (débil) en todos los archivos `.env`.
- AGENTS.md sección 8 (SEC-01) clasifica el fallback JWT como **crítico**: "No confiar en JWT si `JWT_SECRET` no está definido".
- AGENTS.md sección 3.2 prohíbe versionar `.env.docker` y `.env.production`; al trabajar solo en modo local, estos son redundantes.
- Se generaron los secretos con Node.js (v22.15.0 disponible) usando `crypto.randomBytes()`, que produce entropía criptográficamente segura.
- Los valores **no** se exponen en logs ni en el repositorio: los secretos viven solo en `.env.local` (gitignored) y `backend-materiales-go/.env` (gitignored).

### Dónde están los cambios
- `.env.local` — contiene los nuevos `JWT_SECRET` y `DB_PASSWORD` (gitignored, no versionado).
- `backend-materiales-go/.env` — contiene la nueva `DB_PASSWORD` (gitignored, no versionado).
- `.env.example` — placeholders seguros actualizados (versionado).
- `.env` — eliminado (consolidado en `.env.local`).
- `.env.docker` — eliminado (no necesario en modo local).
- `.env.production` — eliminado (no necesario en modo local).

### Dónde se guardaron los valores reales (sin exponer)
- Los valores reales de `JWT_SECRET` y `DB_PASSWORD` se escribieron directamente a `.env.local` (raíz del proyecto) y `backend-materiales-go/.env`.
- **Ningún valor real aparece en este documento, en logs, o en el repositorio.**
- El archivo `.env.local` está excluido de Git mediante `.gitignore` (patrón `.env.*`).
- El archivo `backend-materiales-go/.env` está excluido de Git mediante `.gitignore` (patrón `**/.env`).

### Acción requerida por el humano
⚠️ **El Ing. Botet S.Y. debe actualizar la contraseña de PostgreSQL manualmente** para que coincida con la nueva `DB_PASSWORD` generada en `.env.local`. Los servicios que usan Sequelize y GORM leerán la nueva contraseña al reiniciarse.

### Cómo verificar
```bash
git check-ignore .env.local backend-materiales-go/.env .env .env.docker .env.production
# Devuelve las rutas si están correctamente ignoradas (salida vacía = error = NO ignorados)
# .env.example NO debe aparecer (no está ignorado)
```

### Comandos ejecutados (sin valores)
```bash
# 1. Generar JWT_SECRET y DB_PASSWORD + actualizar .env.local y backend-materiales-go/.env
node -e "
const fs = require('fs');
const crypto = require('crypto');
const newJwtSecret = crypto.randomBytes(32).toString('hex');
const newDbPassword = crypto.randomBytes(24).toString('hex');
let envLocal = fs.readFileSync('.env.local', 'utf-8');
envLocal = envLocal.replace(/^JWT_SECRET=.*/m, 'JWT_SECRET=' + newJwtSecret);
envLocal = envLocal.replace(/^DB_PASSWORD=.*/m, 'DB_PASSWORD=' + newDbPassword);
fs.writeFileSync('.env.local', envLocal);
let goEnv = fs.readFileSync('backend-materiales-go/.env', 'utf-8');
goEnv = goEnv.replace(/^DB_PASSWORD=.*/m, 'DB_PASSWORD=' + newDbPassword);
fs.writeFileSync(goEnv, goEnv);
console.log('JWT_SECRET length: ' + newJwtSecret.length);
console.log('DB_PASSWORD length: ' + newDbPassword.length);
"

# 2. Eliminar .env files no necesarios en modo local
Remove-Item -Path .env -Force
Remove-Item -Path .env.docker -Force
Remove-Item -Path .env.production -Force

# 3. Verificar .gitignore
git check-ignore .env.local .env.example backend-materiales-go/.env
```

### Qué hemos aprendido
- Tener múltiples `.env.*` archivos (`.env`, `.env.local`, `.env.docker`, `.env.production`) con valores duplicados crea riesgo de confusión y fugas: el valor débil `el_token_mas_seguro_del_mundo_2025` estaba replicado en 4 archivos distintos.
- `.gitignore` ya excluía correctamente todos los archivos `.env` y `.env.*` salvo `.env.example`, pero la consolidación a un solo archivo `.env.local` reduce la superficie de error.
- La verificación con `git check-ignore` es la herramienta adecuada para confirmar que los secretos no están versionados.

### Dependencias desbloqueadas
- TASK-A-08: Eliminar fallback `JWT_SECRET || "secreto"` (depende de que el `JWT_SECRET` esté rotado y bien definido).
- TASK-A-09: Añadir JWT middleware a Materials Service (Go).
- TASK-A-07: Verificar `.env.example` (completado como parte de este cambio).

## ADR-004: Prediction Service en Python + FastAPI

**Decisión:** Crear `prediction-service/` como servicio aparte en Python 3.11+ + FastAPI.

**Justificación:**
- Ecosistema ML maduro en Python (scikit-learn, XGBoost, Prophet, TensorFlow).
- Ciclo de vida independiente (entrenamiento, versionado, despliegue).
- Escalabilidad separada.
- Aislamiento de fallos.

**Alternativas descartadas:**
- Node.js: ecosistema ML limitado.
- Go: ecosistema ML muy limitado.

**Consecuencias:**
- Nuevo lenguaje en el stack (Python).
- Nueva BD (`bd_predictions`).
- Servicios auxiliares: MLflow (model registry), Airflow (pipelines).
- 19 tareas nuevas en Fase D.

## ADR-006: Docs Bilingües ES/RU (Archivos Paralelos)

**Decisión:** Usar archivos paralelos `nombre.es.md` / `nombre.ru.md` en `docs/`.

**Justificación:**
- Cumple requisito de tesis bilingüe (RU para defensa, ES para publicaciones).

- Carpetas por idioma (`docs/es/`, `docs/ru/`): duplicación de estructura.
- Un archivo con dos secciones (`## ES` / `## RU`): archivos muy largos.

**Consecuencias:**
- 18 documentos × 2 idiomas = 36 archivos.
- Fase C (12 tareas) para traducción.
